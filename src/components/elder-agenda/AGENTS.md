- The SC sees the elder agenda in three presentation modes (read/prepare/build) inside ElderAgendaView; read mode edits SC-only fields one at a time and autosaves, and SC saves send knownResponseIds so responses that arrived after loading are kept (mergeScAgenda), because a stale screen must never erase elders' answers; installed versions without that field keep the old full-replace behavior.
- Elders (account or code) only see the SC's last "Enviar pauta para os anciãos" (published_payload/published_at); their answers and elder-editable card content still live in payload and are overlaid by card id (elderView), because SC drafts must never leak while responses must arrive at once; attachments still in the sent version stay in the cloud until the next send.
- The agenda per-topic time is an optional row attached to the timer card (AgendaTopicRow, device-local toggle) with its own clock (topic-clock.ts, localStorage per visit, shared by read mode and fullscreen), because topic play/pause and topic changes must never start or stop the main timer.
