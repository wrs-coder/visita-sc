- After a write, cached reads of that table and read server functions are only marked stale (response-cache.ts), never deleted, so offline reads never lose data.
- Field items requested from elders: requested_fields (copied on apply); NULL on a visit row = legacy visibility, so old visits keep fields.
- Per-tab Bible (outlines/reading) is device-local via getActiveLibrary(scope), falling back to the global active Bible, so unset users see no change.
- Reading lateness is tracked per weekday inside the WeekdayPlan (lastRead[7] + since floor, reading-day-log.ts), never from a shared last-read date, so it travels in backups and one day's reading never clears another day; plans without since are seeded to today so restores never raise surprise alerts.
- Big-event transfer file (.visitasc, event-share-file.ts) never carries PINs, tokens or links, because the receiving device generates its own.
- Program import rules (numbering, auto type, Oração/Presidente parts) live only in big-events/program-rules.ts and run after every parser except .visitasc; part extras are "@extra:" markers inside talk_includes and Oração/Presidente never advance times, so no schema change is needed.
- Big-event time control (event-timer.ts) is device-local per event in localStorage, computed from Date.now (spent ms + active start), with series items summed inside the series head and counted once in the program; the Android overlay is the FloatingTimer plugin/service (notification fallback), because it must work offline with no schema change.
- Time-control display mode (countdown/stopwatch) and first real start per part are device-local in event-timer.ts; the start pill compares that real start with the program time only on the event day, because a timer test on another day must not show huge delays.
