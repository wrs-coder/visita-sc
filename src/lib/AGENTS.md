- After a write, cached reads of that table and read server functions are only marked stale (response-cache.ts), never deleted, so offline reads never lose data.
- Field items requested from elders: requested_fields (copied on apply); NULL on a visit row = legacy visibility, so old visits keep fields.
- Per-tab Bible (outlines/reading) is device-local via getActiveLibrary(scope), falling back to the global active Bible, so unset users see no change.
- Reading lateness is tracked per weekday inside the WeekdayPlan (lastRead[7] + since floor, reading-day-log.ts), never from a shared last-read date, so it travels in backups and one day's reading never clears another day; plans without since are seeded to today so restores never raise surprise alerts.
- Finished visits are remembered on-device (finished-visits.ts) and filtered from the overdue list, because cached reads must never bring back 'Finalizar agora'.
- External links open via external-link.ts: real <a target=_blank> in the browser, Capacitor Browser in the app, never inside the app's own frame, because YouTube refuses framing.
- The header/sidebar Sync button syncs only the open screen's mirror tables (screen-sync.ts route map, unmapped routes fall back to full sync); full sync lives in Profile and auto-sync runs once a day from 02:00 + per-device jitter, because full syncs waste time and server load.
- Live big-event responses are merged into the mirror via patchMirrorRow (no cursor/updatedAt change) and BigEvents re-pulls parts online, because speaker answers arrive off-device and stale mirror reads reverted statuses.
- The time-control clock mirror sends a small snapshot (elapsed ms at send time, built in timer-mirror.ts) over a Realtime broadcast-only channel named by a random device code, or via the Android TimerMirrorServer plugin (read-only GET / and /state on the hall Wi‑Fi); the tablet keeps counting on its own clock, because no table or schema change is allowed and the hall may have no internet. The QR uses the open https origin in a browser (preview or official) and the official domain in the app, so previews never point at an unpublished site.
- The mirror viewer keeps the last snapshot in localStorage per code (6 h) and never drops a counting clock on an empty/failed response; the speaker Mini tempo is the same channel filtered by ?p=<partId> using snapshot speakers/done, floating via canvas→video Picture-in-Picture, because reloads must not show 'Aguardando' and no schema change is allowed.
- Congregation import parses on-device (congregation-import.ts) via createCongregation; no schema change.
- Big-event speaker import (speaker-import.ts) parses csv/xlsx/docx/pdf on-device (pdfjs lazy), matches talks by outline number and Presidente/Oração parts by session time, lets the user retarget (swap) or edit each row, and applies only reviewed rows through patchSpeaker; Programação espiritual PDFs, the app's own Programa PDF and Designações Word files have dedicated readers; official Running Program PDFs are read first by column positions (Nº from "N.x:" in the theme, smaller-font lines under the name = congregation), then the generic line reader fills the rest, because older formats must keep working unchanged.
- syncTables always runs inside withNetworkWindow and marks pulled tables stale in response-cache, because otherwise the local-first fetch answers the pull from the mirror and other devices' rows never arrive.
- Big events: 'Baixar da nuvem' merges cloud rows with device-only events (marked 'Só neste aparelho', sent via 'Enviar todos'), per-event receive replaces that event, and an empty sync never clears a non-empty list, because same-stamp rows marked deleted on the device never come back via incremental pull. Dated big events are deleted server-side 2 days after event_date by the existing daily cleanup job; deletes leave sync tombstones and the merge drops tombstoned or expired device-only events, because re-uploading them resurrected deleted events.
- Read-cached list screens may confirm an empty cached answer once against the network (fresh-if-empty.ts), because a stale empty copy hid existing templates until re-login.

- TNM 'Conteúdo do livro' and chapter-navigation files are skipped by structure (bible-outline-guard.ts) and outline-like verse texts are hidden at read time, because old imports stored them as fake chapter-1 verses and stored scripture must not be rewritten.
- Per-chapter verse counts come from the TNM nav line (bibleversenav "1 - N") at import, are stored optional as BibleLibrary.verseCounts and trim extra verses; missing = no checking, because old imports must keep working unchanged.
- Screen titles come from src/lib/page-titles.ts (route → i18n key) and render in the mobile top bar / md+ slim bar; page <h1>s stay as sr-only, because titles inside the content wasted screen space and screen readers still need them.
- Midweek meeting programs live only on-device (meeting-store.ts, localStorage per user), are parsed from workbook .rtf/.zip on the device (mwb-import.ts, size/entry limits) and timed by the unchanged EventTimerFocus with id "meeting-<id>"; the hub opens from a free ⏱ header button and loads lazily, because it must not depend on any Agenda appointment nor weigh on the dashboard.
- "Para comentar" lists only starred highlights (commentList), and the dashboard Esboços card reuses the same CommentCard/CommentMode over the user's local workspace, because both places must show exactly the same notes.
- The visit week fills empty comments/closing-prayer song with the visit program's midweek chairman/closing prayer at display time only. Meeting counsel is an optional minutes field on the part, emitted as its own speakerless timer slot (id suffix ::counsel); the visit week swap (visit-week-meeting.ts) is applied only at display/timer time and the board PDF (visit-week/board-program.ts, two templates full/simple chosen per device, shared detailed field table) is a pure model + pdf-lib render that lists the same parts/counsel/start times as the timer (program picked by meeting date, else workbook week overlapping the visit) with optional phrases toggled per device, because stored meeting programs must stay unchanged.

- Elder meeting agenda (elder_meeting_agendas, no client grants): all access via elder-agenda.functions.ts; payload v2 is an ordered block list (legacy fixed fields converted at read time) where only the SC changes structure/deadline and others merge content of blocks they may edit until the deadline (mergeAgenda), because per-block permissions can't be expressed in RLS. SC agenda templates live in owner-only elder_agenda_templates (default one seeds new agendas server-side); the last loaded agenda is cached on-device per visit/invite code for offline read-only use.
