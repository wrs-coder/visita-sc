- After a write, cached reads of that table and read server functions are only marked stale (response-cache.ts), never deleted, so offline reads never lose data.
- Field items requested from elders: requested_fields (copied on apply); NULL on a visit row = legacy visibility, so old visits keep fields.
- Per-tab Bible (outlines/reading) is device-local via getActiveLibrary(scope), falling back to the global active Bible, so unset users see no change.
- Reading lateness is tracked per weekday inside the WeekdayPlan (lastRead[7] + since floor, reading-day-log.ts), never from a shared last-read date, so it travels in backups and one day's reading never clears another day; plans without since are seeded to today so restores never raise surprise alerts.
- Big-event transfer file (.visitasc, event-share-file.ts) never carries PINs, tokens or links, because the receiving device generates its own.
- Program import rules (numbering, auto type, Oração/Presidente parts) live only in big-events/program-rules.ts and run after every parser except .visitasc; part extras are "@extra:" markers inside talk_includes and Oração/Presidente never advance times, so no schema change is needed.
- Big-event time control (event-timer.ts) is device-local per event in localStorage, computed from Date.now (spent ms + active start), with series items summed inside the series head and counted once in the program; the Android overlay is the FloatingTimer plugin/service (notification fallback), because it must work offline with no schema change.
- Time-control display mode (countdown/stopwatch) and first real start per part are device-local in event-timer.ts; the start pill and the top 'Programa' line compare real phone time-of-day with the program times on any day (before starting, lateness shows only on the event day), because the user wants deviation by the phone clock.
- Program timing: speaker parts imported from .rtf get the gap minus 1 min, and auto start times add 1 transition min after durations ending in 4/9 (advanceMin in invite.ts), because outlines are always 1 min shorter than the slot.
- Finished visits are remembered on-device (finished-visits.ts) and filtered from the overdue list, because cached reads must never bring back 'Finalizar agora'.
- External links open via external-link.ts: real <a target=_blank> in the browser, Capacitor Browser in the app, never inside the app's own frame, because YouTube refuses framing.
- Renaming a big-event speaker who already had an invite renews the personal link or PIN and resets status to pending (patchSpeaker + letter-pick.ts), because the old invite belongs to the previous speaker.
- The header/sidebar Sync button syncs only the open screen's mirror tables (screen-sync.ts route map, unmapped routes fall back to full sync); full sync lives in Profile and auto-sync runs once a day from 02:00 + per-device jitter, because full syncs waste time and server load.
- Live big-event responses are merged into the mirror via patchMirrorRow (no cursor/updatedAt change) and BigEvents re-pulls parts online, because speaker answers arrive off-device and stale mirror reads reverted statuses.
- Letter formatting is light markup inside template text (**bold**, *italic*, ==mark==, "• " bullets, letter-markup.ts) plus optional layout/boxes fields in the template JSON; missing fields = automatic fit, because old templates and letter_templates sync must keep working unchanged.
- The default letter template carries no personal header data; repairInheritedTemplates swaps header fields inherited from the old IBE-01 default for the account's profile on fetch, because every new account used to receive another circuit's letterhead.
- The time-control clock mirror sends a small snapshot (elapsed ms at send time, built in timer-mirror.ts) over a Realtime broadcast-only channel named by a random device code, or via the Android TimerMirrorServer plugin (read-only GET / and /state on the hall Wi‑Fi); the tablet keeps counting on its own clock, because no table or schema change is allowed and the hall may have no internet. The QR uses the open https origin in a browser (preview or official) and the official domain in the app, so previews never point at an unpublished site.
- The mirror viewer keeps the last snapshot in localStorage per code (6 h) and never drops a counting clock on an empty/failed response; the speaker Mini tempo is the same channel filtered by ?p=<partId> using snapshot speakers/done, floating via canvas→video Picture-in-Picture, because reloads must not show 'Aguardando' and no schema change is allowed.
- Congregation import parses on-device (congregation-import.ts) via createCongregation; no schema change.
- Big-event speaker import (speaker-import.ts) parses csv/xlsx/docx/pdf on-device (pdfjs lazy), matches by outline number, and applies only reviewed rows through patchSpeaker; official Running Program PDFs are read first by column positions (Nº from "N.x:" in the theme, smaller-font lines under the name = congregation), then the generic line reader fills the rest, because older formats must keep working unchanged.
- syncTables always runs inside withNetworkWindow and marks pulled tables stale in response-cache, because otherwise the local-first fetch answers the pull from the mirror and other devices' rows never arrive.
- Big events: 'Baixar da nuvem' and per-event send/receive (cloud-sync.ts) replace the local mirror with cloud rows, and an empty sync never clears a non-empty list, because same-stamp rows marked deleted on the device never come back via incremental pull. Dated big events are deleted server-side 2 days after event_date by the existing daily cleanup job.
